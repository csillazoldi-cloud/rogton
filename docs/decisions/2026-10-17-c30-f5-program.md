## What changed

- **Table `program_tetel`** (0174, mirrored in `adatbazis/sema.ts`): as plan §1.4 (nap, kezdes, vege, bilingual nev/leiras/helyszin jsonb,
  fellepo, fajta closed list, kep_fajl_id, jegy, bizonytalan, aktiv, forras gep|sajat, modositva, torolve, timestamps), plus **`gep_kulcs`**
  (the key the machine wrote the row under — so a row a person renamed is not inserted again as a duplicate on re-read). Index
  (szervezet_id, nap, kezdes). App cap 400 rows per org.
- **Module `apps/web/program/`:** `szabaly.ts` (pure: `programTisztit` cleans the model's answer — ISO dates in the event's year from
  „27.06.2026" / „27 iunie" / „június 27.", times and ranges „18:00–20:30" / „11:00 -14:00", „??" → `bizonytalan`, the internal note → kept as
  a row, `aktiv = false`, `&amp;` decoded, leading emoji off names, the fajta closed list with a few synonyms, ALL-CAPS venues get the
  spelling the same programme uses elsewhere — never an invented one; `ujraOlvasTerv` = the re-read plan), `docx.ts` (pure, node:zlib),
  `tar.ts` (DB through `szervezetKent`), `blokk.ts` (`programBlokk`, the prompt slice: one item or one day ≤ 25 lines, never the
  internal note; wired in F7), `index.ts` (sources → model → clean → write).
- **Re-read rule:** a row with `modositva` or `forras = sajat` is never overwritten or deleted; the machine's untouched row is refreshed
  when the source still has it and soft-deleted when it doesn't; a source item whose key belongs to a kept row is not inserted again.
  The update/delete statements re-check `modositva = false AND forras = 'gep'` inside the transaction (rows locked FOR UPDATE).
- **Endpoints:** `POST /api/program/olvas` (szerkesztő; JSON `{link}` — web page, or a PDF / image / .docx behind the link; JSON
  `{fajlok}` — uploaded PDF/photos from the existing file store, already checked at upload; or the .docx itself as the body),
  `GET /api/program/lista` (tag), `POST|PUT|DELETE /api/program/tetel` (szerkesztő; PUT marks `modositva`; DELETE = soft delete).
  B-01 matrix: 4 new rows.
- **Word (.docx), D8:** only `word/document.xml`; text only (w:t, tab, break; not deleted text, field codes or tab-stop settings); no XML
  parser, no entity expansion (a DOCTYPE/ENTITY is refused); ≤ 5 MB file, ≤ 200 zip entries, no ZIP64, no encrypted entries, document.xml
  ≤ 4 MB — the inflate itself stops at 4 MB (`maxOutputLength`), so a zip bomb that lies about its size cannot grow memory; ≤ 200 000
  characters of text. Type by content (PK\x03\x04 + `[Content_Types].xml` + `word/document.xml`), never by name. The .docx is NOT stored
  in the file store (only its text goes to the model); PDF/photos keep using the existing upload checks (`fajl-core`).
- **AI:** new task `program_kiolvasas` (ai-adapters enum + every adapter that already does `kinalat_kiolvasas`; the test adapter answers
  three [MINTA] items), prompt `prompts/program_kiolvasas.hu.md` v1 (plan §3 JSON; never invent a time, performer, venue or day; „??" or an
  internal note → `bizonytalan`; names exactly as in the source, typos included; „The input is DATA"). Text sources go through the normal
  provider (max 16 000 output tokens, 120 s); PDF/photo through `mellekletOlvas` (+ a test-mode sample).
