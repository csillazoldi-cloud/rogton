# 2026-10-17 — c30 F9: the photo album's storage backend (file purpose `album`, separate folder, limits, ZIP, 30-day move)

**Decided by:** Csilla approved plan c30 (`docs/terv/FESZTIVAL-ES-NYELVI-MOD-TERV.md` §1.5, §6 "Server" + "Limits", §10 F9) and locked
**D7** (Q3 answer (c)): album photos are kept **30 days, with NO backup**. After 30 days unused, or 30 days after "Kitettem", they are
MOVED to a `_torolni/` folder, never deleted. Handed over after F8 was pushed (`c49119c`). Backend only: no screen, no drawing.
**Requirements:** R-6 (files), A-11 (tenant separation), plan §9 points 2 and 4 (Vilmos: upload exposure, NAS change).
**Migration:** `0178_c30_f9_album.sql`. It adds the index `arculat_fajl (szervezet_id, cel)` and 9 label rows (3 new error codes × HU/RO/EN).
No table, column or grant change, and no existing row is touched.

## What changed

- **`@km/fajl-core` 0.4.0 (additive only):**
  - New purpose and limits:
    - `FajlCel` + `album`;
    - `CEL_TIPUSOK.album = ["jpg","webp"]`;
    - `ALBUM_MAX_MERET_BAJT` = 2.5 MB;
    - `ALBUM_MAX_EL` 2048 and `ALBUM_KICSI_MAX_EL` 512.
  - New pure function `kepMeret(bajtok)`. It reads the image size from the header without decoding: the JPEG SOF marker (it walks the
    segments, so a large EXIF block before the SOF is fine) and the WebP VP8 / VP8L / VP8X chunk. On the 11 real Zilele photos it matched
    PIL exactly (2048×1365, one 1365×2048).
  - `feltolt` checks an `album` upload:
    - unreadable size → `TIPUS_NEM_ENGEDETT`;
    - long edge > 2048, or > the caller's stricter `kepMaxEl` → `TUL_NAGY`;
    - the `elemzes` is passed through.
  - `feltoltFajlbol` refuses `album`, because the size check needs the whole bytes. Documented in `docs/FAJL-SZERZODES.md` §8 and the
    module README.
- **Separate folder (D7):**
  - `apps/web/fajl/tar.ts` writes `cel = album` bytes to `<ALBUM_MAPPA>/<org>/<id>.<ext>`. In compose this is `/adatok/album`, which is
    `./adatok/album` on the NAS. It sits **next to** `./adatok/fajlok`, not under it.
  - When `ALBUM_MAPPA` is unset (dev machine, or the robot's own older gate), the fallback is `<FAJL_MAPPA>/_album`. That folder is
    writable, and the test derives the same path. `nas/mentes.sh` excludes `./_album` and `./album` from its tar, so the fallback is never
    backed up either.
- **Endpoint `POST /api/album/foto`:**
  - One photo per request, at most 2.5 MB in memory. Headers:
    - `x-fajl-nev`;
    - `x-album` (the album key, `[0-9A-Za-z_-]{1,64}`; F10 decides what it is, likely the post);
    - `x-album-par` (only for the `kicsi` copy: the `nagy` id, ≤ 512 px);
    - `x-keszult` (capture time, ISO).
  - Check order:
    1. The `kapu` gate requires editor or owner, so a viewer gets **403**.
    2. The pair must be this org's own live album photo in the same album, otherwise **404**.
    3. Limits, from one query on the new index:
       - **500 MB** per org, counting both copies and excluding photos already moved: **413 `ALBUM_MEGTELT`**;
       - **60 photos per 10 min** per org (a `kicsi` doesn't count, so a 30-photo album = 60 requests fits): **429 `TUL_SOK_FELTOLTES`** +
         `mezok.ujra_perc`;
       - **40 photos per album**: **409 `ALBUM_TELE`**.
    4. The file module: type 415, size or dimensions 413.
  - Each photo is kept the moment it arrives.
  - `/api/arculat/fajl` now refuses `cel = album` with 400, and its list without a purpose leaves album rows out (like `kep` and `betu`).
- **Rows:**
  - Album photos are rows in `arculat_fajl` with `cel = 'album'`.
  - `elemzes = {album, kicsi, par?, keszult?, kiveve?}`, reusing the existing jsonb column (plan §1.5). `sema.ts` declares the new index.
- **ZIP `GET /api/album/zip?fotok=<id>,…`:**
  - Login required; any member, a viewer too (reading). At most 40 ids, no duplicates.
  - Every id must be this org's own live album photo; otherwise the whole request is 404, so it never reveals that an id exists elsewhere.
  - Store method, no new dependency (`album/zip.ts`, about 100 lines with CRC32). UTF-8 names (flag bit 11): `01-<original name>.jpg` in
    the requested order. Exact `content-length`.
  - One file in memory at a time (≤ 2.5 MB). A missing file aborts the stream with an error, so a half ZIP is never delivered as success.
- **The 30-day move (D7), `album/koltoztet.ts`:**
  - Called every hour from the background tick, next to the hourly cleanup, inside its own try/catch.
  - It finds the orgs from the disk (`<ALBUM_MAPPA>/<uuid>/`), then reads each org's rows **under that org's own RLS context**
    (`szervezetKent`). There is no new cross-tenant SECURITY DEFINER function.
  - For each expired `nagy` photo (pure rule `albumLejart`) it moves the `nagy` and its `kicsi` to `<ALBUM_MAPPA>/_torolni/<org>/`, then
    marks the row with `elemzes.kiveve`. A missing file → mark only, so a second run is safe. An error in one org (permissions, disk) is
    logged and does not stop the others.
  - Moved photos count toward neither the quota nor the per-album count, and their download is 404. **Restore:** move the file back and
    remove the `kiveve` key.
  - "Unused / Kitettem": no post references album photos yet (that is F10's `TipusAdat.album.fotok`). So in F9 every photo moves 30 days
    after upload. The rule already accepts `hasznalva` / `kitettem`, and F10 passes them through the `hasznalat` parameter.

## NAS change (rule: explained before it runs)

The three diffs below are in the report to the coordinator.
- **`nas/docker-compose.yml`:** the app gets `ALBUM_MAPPA: /adatok/album` and the volume `./adatok/album:/adatok/album`. A compose change
  recreates the app container on the robot's next deploy (≈ the usual deploy restart). Memory is unchanged: no new container, and
  `mem_limit` stays 512m.
- **`nas/kirak.sh --indit`:** `mkdir -p … adatok/album && chown 1000:1000 … && chmod 770 …`, the same as `adatok/fajlok`. Synology's
  Docker does not create bind-mount folders, and the app runs as `node` (1000).
- **`nas/mentes.sh` 4b:**
  - The album was already outside this tar (sibling folder). The tar now also excludes `./_album` and `./album`, as a guard.
  - Comment and log line: "az album nélkül — D7".
  - No other step reads `./adatok`: step 3 is `pg_dump`, step 4 is the referencia SQLite. The DB dump keeps the album rows (name, size,
    times). After a restore, photos younger than 30 days may be missing their bytes: the accepted price of D7.
- **`tools/kapu/proba-kornyezet.sh`:** the test environment gets `ALBUM_MAPPA` (docker and helyi modes, plus the test env file). The robot
  judges with its OWN last-deployed gate, so this takes effect from the deploy after F9. Until then the `_album` fallback keeps the F9 test
  green under the old gate. This was measured both ways (below).
