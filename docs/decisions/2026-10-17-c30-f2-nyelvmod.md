# 2026-10-17 — c30 F2: post language mode + second language + the „Más nyelven” menu as a union

**Decided by:** Csilla approved F2 on 2026-10-17 (plan c30, `docs/terv/FESZTIVAL-ES-NYELVI-MOD-TERV.md` §1.3, §5 „Más nyelven”, §10 F2).
**Requirements:** R-14/R-15 (UI, communication and material languages are separate settings), R-01. **Migration:** none.
**RLS:** unchanged. **Default = today's behaviour.**

## What changed

- **contracts:** `POSZT_NYELV_MODOK = ["egy", "egyben", "kulon"]`, type `PosztNyelvMod`; profile field `poszt_nyelv_mod` — a plain string
  (F0 rule), read only through `nyelvMod()`. Nothing writes it yet (the setup step D5 and the Settings switch D9 are F3); it is a known
  non-core field, so `profilTar.mezoMent` already accepts it.
- **profile-core (pure):**
  - `nyelvMod(profil)`: 0 or 1 content language → `egy` (nothing to pair, even if a mode is stored); otherwise the stored mode when it is
    one of the three, else `kulon` — every org with two or more languages today has one post per language, reached by „Más nyelven”.
  - `masodikNyelv(profil)` = `nyelvek[1]` (a known `Tartalomnyelv`) or null. The order of `nyelvek` is the order of a joined post (F3).
  - `masNyelvenLista(nyelvek)`: `hu, ro, en` first (exactly today's menu, nothing removed), then every other profile language in profile
    order; unknown codes and duplicates dropped.
- **Posztszöveg (`app/poszt/R15Poszt.tsx`, `page.tsx`):** the hard-coded `["hu","ro","en"]` menu is now `masNyelvenLista(profil.nyelvek)`.
  hu/ro/en keep their `poszt.nyelv_*` labels; any other language is named by the existing `nyelvNev` helper (`Intl.DisplayNames`, the
  same way Szervezet adatai names languages) — so no new labels and no migration. The server already accepted any `Tartalomnyelv` for a
  cell and a translation (`PosztNyelv = Tartalomnyelv`), so picking „németül” writes a German cell through the existing translation path.
