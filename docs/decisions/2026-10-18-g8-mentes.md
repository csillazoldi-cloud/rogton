## What is backed up, and how

One file per night: `~/gma/mentes/napi/<YYYYMMDD-HHMM>.age` = an age-encrypted tar of
- `km.dump` — `pg_dump -Fc` inside `gma-db`: one consistent snapshot, restorable table by table;
- `fajlok-album.tar` — `~/gma/adatok/fajlok` + `album`, read through a throwaway `gma-app:aktiv` container as root, network
  none, read-only mount. The app owns those folders (uid 1000, mode 770), so gyorsadmin cannot read them directly, and it has no
  sudo — the container is the no-sudo way in (same trick as kirak.sh's chown);
- `MANIFEST` — date, live commit, sha256 of both parts, row counts of `fiok`/`szervezet`, number of files.

Before encryption the dump is read back (`pg_restore -l`), so an unreadable dump never becomes "last night's backup". The
plaintext parts live only during the run in `~/gma/mentes/.munka` (700) and are removed after encryption: they are by-products,
not data, and moving them to `_torolni/` would leave an unencrypted copy beside the encrypted one. The run takes the deploy lock
(waits up to an hour), so a backup never races a migration. 03:40 Budapest, `Persistent=true` (a night missed while the box was
off runs after boot), idle IO priority.

What is NOT in it: `~/gma/.env` (secrets — they live in Csilla's vault and are re-created by the batches), the WARP registration
(`adatok/warp`, re-registers by itself), images (rebuilt from git), the pre-migration dumps in `~/gma/mentes/` (kirak.sh's own).

## Encryption: age, public key on the box — not openssl with a passphrase

Chosen: **age** (`apt install age`, in the one sudo batch of G8; it is in Ubuntu's universe repository, not installed by default).
- The Gigabyte holds only the **public** key (`~/gma/mentes-kulcs.pub`). It can write backups but cannot read them back. The
  private key lives only in Csilla's vault on the Mac (`~/saas/vault/rogton-mentes-kulcs`).
- openssl with a passphrase file would put the decryption secret on the same disk as the backups: anyone who gets the box or
  the backup folder gets both. That defeats the point of encrypting a copy that sits next to the live data anyway; the encryption
  matters for the copies that leave the box (the Mac pull, any later cloud copy).
- Cost: the restore drill cannot decrypt on the Gigabyte. The Mac decrypts and streams the plain tar over ssh into the drill
  (`age -d … | ssh gma 'bash ~/admin/uzem/mentes-visszatolt.sh -'`). Accepted — it also proves on every drill that the vault key
  is the right one.
- `mentes.sh` refuses to run if the key file is not an `age1…` public key, and refuses loudly if it contains a secret key.

## Off-box copy: the Mac pulls — not a push to the office NAS

- The office NAS sits inside the range the G6 fence blocks for gma containers, and gyorsadmin holds no credentials for
  anything off the box. Giving it NAS credentials would turn the box into a path into the NAS — the opposite of the fence.
- Pull from the Mac (`uzem/mentes-lehuz.sh`, ssh alias `gma`, which Csilla already has): the Gigabyte never initiates anything.
  Keeps 30 on the Mac (older → `_torolni/`), checks sizes, and test-decrypts the newest with the vault key — a backup nobody can
  open is not a backup.
- Weakness, stated: the copy happens when Csilla runs it (or when she schedules it on the Mac). Until then the only copy is on
  the box. Open item: schedule it on the Mac (launchd) once she says so.

## Restore drill

`uzem/mentes-visszatolt.sh` restores one backup into a throwaway `gma-proba-db` (same image and ICU locale as `gma-db`, no
network, data in tmpfs), checks the sha256s from the manifest, runs `pg_restore --exit-on-error --no-owner`, prints `fiok` /
`szervezet` counts next to the manifest's, counts the files, and removes the container. Green only when everything matches.
The live database is never touched. A real restore is a decision, not a script: the Runbook in `uzem/README.md`.

## Heartbeat

`uzem/szivdobbanas.sh` every 10 minutes: `/api/egeszseg` = 200 on 127.0.0.1:8410, and `warp=on|plus` through gma-app's own
network (the path the downloader and the AI calls take). Skipped while a deploy holds the lock. A failure appends one line to
`~/gma/allapot/riasztas`; healing appends a `helyreállt` line. Telegram is optional and off by default: only when both
`RIASZTAS_TELEGRAM_TOKEN` and `RIASZTAS_TELEGRAM_CHAT` are set in `~/gma/.env`, and then only on the transitions (outage starts,
outage heals). New names on purpose: the template lists the app's old `TELEGRAM_*` variables as removed, and these are read only
by the host script, never passed into a container. The token never appears on a command line (curl reads the URL from stdin).
Log hygiene rides along: `~/gma/naplo` files older than 90 days move to `~/gma/_torolni/naplo/`.
